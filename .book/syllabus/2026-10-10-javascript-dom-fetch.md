| 항목 | 내용 |
|---|---|
| 학습목표 | JavaScript 문법을 익힌다. DOM을 제어해 순수 JavaScript와 HTML만으로 fetch 통신하는 프론트엔드를 만든다. |

## 가정한 것
- 강의방법이 이론·실습 혼합이라 이론·실습 중심 구성을 쓴다. 브리프 고정 조건의 프로젝트형 항목은 쓰지 않는다.
- Node.js는 22 LTS로 한다.
- VS Code, Live Server, Node.js는 이미 설치되어 있다고 보고 1장에서는 설치 확인만 한다.
- 브리프에 없는 콘솔 미니프로젝트(9장)를 문법 묶음 끝에 넣었다. 여기서 만든 데이터 함수를 14장에서 복사해 다시 쓴다.
- CSS Grid는 DOM 미니프로젝트 뒤(15장)에 둔다. 1장부터 연결해 쓴 공통 CSS를 이 장에서 풀어 설명한다.
- CSS Grid는 기본 문법만 다룬다. 반응형 카드와 grid-template-areas는 뺀다.
- React 기반으로 단축 평가(&&, ||, ??)와 옵셔널 체이닝을 더했다.
- ES6 객체 리터럴 단축 문법(단축 속성, 계산된 속성 이름)을 6장 앞에 더했다. 메서드 단축 문법은 뺀다.
- 6-1, 6-5, 7-6, 12-2, 13-3에 더한 내용은 React 모양에 맞추지 않고 순수 JavaScript로 가장 쉽게 쓴다. 입력은 input 이벤트로 처리한다.
- 고차 함수는 forEach·map·filter·find만 다룬다.
- 원본을 바꾸지 않는 배열 메서드로 slice를 더한다(7-6). concat은 전개 연산자가 대신하므로 뺀다. 원본을 바꾸는 splice도 뺀다.
- var, while, 스코프는 다루지 않는다.
- 에러 시연을 장마다 넣는 틀로 쓰지 않는다. 에러를 막는 기술(옵셔널 체이닝 등)은 막기 전 에러를 보이고, 오류 처리는 fetch 실패 처리(18~20장)에서 다룬다.
- 동적 UI는 상태 배열을 바꾸고 render 함수로 다시 그리는 방식으로 통일한다. React의 사고방식과 같다.
- JSONPlaceholder는 POST·PUT·DELETE 결과를 저장하지 않는다. 화면은 응답을 받아 불변 업데이트로 반영한다. 검색은 받아 온 목록을 filter로 거른다.
- 가짜 서버라 동작 확인만 한다. 시연은 1번을 수정·삭제하고 한 번 등록해 101번을 받는다.
- 2026-10-10 6~20장 결정
  - 코드는 가장 쉬운 쪽으로 쓴다. 있는 요소를 찾아 채울 때는 innerHTML, 새 요소를 만들어 붙일 때는 createElement를 쓴다. textContent는 꼭 필요할 때만 쓴다.
  - 이름 있는 함수는 function 선언문으로 쓴다. 콜백(고차 함수, setTimeout)은 안쪽에 화살표 함수로 쓴다.
  - 이벤트 처리 함수는 function 선언문으로 만들고 addEventListener에 이름을 넘긴다. 짧아도 선언문으로 쓴다. 이름은 handleClick, handleSubmit처럼 역할이 드러나게 짓는다. 특정 인자를 넘길 때만 짧은 화살표 함수를 쓴다. 이벤트 객체 매개변수는 e다.
  - 새 id는 nextId를 ++로 올려 정한다. +=는 쓰지 않는다.
  - 새 내장 기능은 처음 쓰는 곳에서 짧게 소개한다. join(7-3), Math.round(9-4), Number(12-4), trim(13-2), throw(18-5), includes(20-4)
  - 로딩 표시는 다루지 않는다. 요청이 빨라 거의 보이지 않는다.
- 제외: 클래스와 프로토타입, localStorage, 모듈, Promise 직접 구현, then·catch, 마이크로태스크, Promise.all, setInterval·clearTimeout, PATCH, HTML·CSS 기초(Grid 제외), jQuery·XMLHttpRequest, Node.js 백엔드, TypeScript·번들러
- 뺀 세부 문법: 부모·자식·형제 탐색, closest, keydown, stopPropagation, 나머지 요소·속성(...rest), 구조분해 이름 바꾸기·중첩, structuredClone, innerHTML 보안 위험

### 6장. 구조분해 할당과 전개 연산자
- 6-1 객체 리터럴 단축 문법
  - ES6 객체 리터럴 문법이다. 변수 이름과 속성 이름이 같으면 { title, content }처럼 줄여 쓰고, [key]: 값으로 속성 이름을 변수로 정한다. [key] 예제는 makeField(key, value)가 { [key]: value }를 돌려주는 함수다.
  - 이유(단축 속성): 변수에 담아 둔 값으로 객체를 만들 때 { title: title, content: content }처럼 같은 이름을 두 번 쓰지 않는다. 속성이 많아질수록 코드가 짧아지고 오타가 줄어든다.
  - 이유(계산된 속성 이름): 바꿀 속성 이름이 코드를 쓸 때가 아니라 실행할 때 정해지면(입력칸 이름처럼 변수에 담긴 이름) 점 표기법으로는 쓸 수 없다. [key]로 쓰면 속성마다 코드를 따로 만들지 않고 하나로 처리한다.
- 6-2 배열 구조분해
  - 배열 값을 변수로 한 번에 꺼낸다. 기본 꺼내기만 다룬다.
- 6-3 객체 구조분해와 매개변수 구조분해
  - 객체 속성을 꺼내고 함수 매개변수에서 바로 푼다. 기본값도 정한다. 6-1의 단축 문법과 모양은 같고 방향이 반대다. React props의 기본 형태다.
- 6-4 값과 참조
  - 객체를 할당하면 같은 대상을 가리키는 모습을 본다. 2장 이름표 비유를 이어 두 이름표가 상자 하나에 붙은 그림으로 보인다.
- 6-5 전개 연산자로 복사하기
  - ...으로 배열·객체를 복사하고 합친다. { ...원본, 속성: 새 값 }으로 한 속성만 바꾼 새 객체를 만들고, 6-1의 [key]와 합쳐 { ...원본, [key]: 새 값 }도 쓴다.
  - 이유: 원본 객체를 그대로 두고 바뀐 객체를 새로 만들 수 있다. 바꾸지 않는 속성을 하나하나 옮겨 적지 않아도 된다.
- 6-6 얕은 복사와 깊은 복사
  - 전개 연산자는 안쪽 객체까지 복사하지 않는 문제를 보이고, 안쪽 객체도 전개해 복사한다. 깊은 복사는 용어만 소개한다. 실습은 8-4에서 한다.
- 연습문제
  - 사용자 객체에서 필요한 값만 꺼내 출력
  - 설정 객체를 복사해 원본을 지키며 값 바꾸기

### 7장. 배열과 불변성
- 7-1 불변성
  - 원본을 바꾸지 않고 새 값을 만드는 이유를 안다. React 상태 관리의 전제다.
  - 이유: 원본을 바꾸면 이전 값이 사라져 무엇이 바뀌었는지 알 수 없다. 새 값을 만들면 ===로 바뀌었는지 바로 안다(6-4 참조와 이어짐).
- 7-2 forEach
  - 반복문 대신 배열을 돈다. 두 번째 매개변수 index는 여기서만 소개한다.
- 7-3 map
  - 배열을 같은 길이의 새 배열로 바꾼다. React 목록 렌더링의 기본이다. 끝에 join 문법을 짧게 설명하고, map으로 만든 태그 문자열 배열을 join("")으로 잇는 예제를 보인다.
- 7-4 filter
  - 조건에 맞는 것만 남긴 새 배열을 만든다. 끝에 filter(...).map(...)처럼 이어 쓰는 메서드 체이닝을 보인다.
- 7-5 find
  - 조건에 맞는 항목 하나를 찾는다. 못 찾으면 undefined이므로 3장의 ?.와 ??를 이어 쓴다.
- 7-6 slice
  - 시작·끝 인덱스로 배열의 일부를 새 배열로 꺼낸다. 원본은 바뀌지 않는다. 전개 연산자와 합쳐 [...arr.slice(0, i), 새 항목, ...arr.slice(i)]로 중간에 넣은 새 배열을 만든다.
  - 이유: 글 100개 중 앞의 10개, 최근 3개처럼 일부만 보여 줄 일이 많다. 반복문으로 옮겨 담지 않고 한 줄로 꺼내며, 원본을 지키므로 불변성 규칙과 맞는다.
- 7-7 push와 전개 연산자
  - push로 넣을 때와 ...으로 새 배열을 만들 때의 차이를 비교한다. 실습: 두 방식으로 할 일 추가하고 원본 비교
- 연습문제
  - 학생 목록에서 합격자 이름 배열 만들기
  - 원본을 바꾸지 않고 장바구니에 상품 추가

### 8장. 불변 업데이트로 하는 CRUD
- 예제 소재는 게시글 posts = [{ id, title, likes }]다. 함수는 배열을 받아 새 배열을 돌려주고, 부르는 쪽에서 posts = addPost(posts, ...)로 바꾼다.
- 8-1 배열에 추가하기
  - 7장의 전개 연산자 방식으로 추가 함수를 만든다. 새 id는 nextId를 ++로 올려 정한다.
- 8-2 배열 항목 수정하기

### 12장. 이벤트 처리
- 12-1 addEventListener
  - click, input, submit에 반응한다. 이벤트 처리 함수는 function 선언문으로 만들고 이름을 넘긴다.

  - 이유: 함수 하나를 여러 입력칸에 걸면 어느 칸에서 무슨 값이 들어왔는지 이벤트 객체로만 알 수 있다.

### 13장. 동적 UI 만들기
- 예제 소재는 메모 { id, title, content }다.
- 13-1 상태 배열과 render 함수
  - 데이터를 바꾸고 화면을 다시 그리는 흐름을 잡는다. React의 사고방식과 같다. render는 목록만 다시 그리고 입력칸은 다시 그리지 않는다.
- 13-2 입력 받아 등록하기
  - form submit으로 입력값을 읽고 trim()으로 빈 값을 막는다. 등록 뒤 입력칸은 value = ""로 비운다.
- 13-3 입력칸 여러 개를 함수 하나로 처리하기
  - 제목·내용 입력칸에 name을 달고 두 칸의 input 이벤트에 handleInput 함수 하나를 건다. 함수 안에서 post = { ...post, [e.target.name]: e.target.value };로 바뀐 칸의 값만 새 객체에 담고 render로 다시 그린다.
  - 이유: 입력칸마다 함수를 따로 만들면 칸이 늘 때마다 거의 같은 함수가 하나씩 늘어난다. 칸의 name을 속성 이름으로 쓰면 함수 하나로 끝난다.
- 13-4 수정하기
  - 위 입력 폼을 다시 쓴다. 수정 버튼을 누르면 editingId에 id를 넣고 입력칸에 값을 채운다. submit에서 editingId가 있으면 수정하고 없으면 등록한다.
- 13-5 삭제하기
  - 위임으로 누른 항목을 지운다. 실습: 메모 목록 등록·수정·삭제
