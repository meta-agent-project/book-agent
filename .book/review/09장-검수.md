## 추천 근거
- 12: 다른 선택은 삼항 연산자를 뺀 `getProgress()`를 실행해 `NaN%`를 보이는 코드 조각이다. 0 나누기는 에러가 아닌 잘못된 값이고, 계획서는 에러 시연을 틀처럼 넣지 않는다고 정했으므로 이유 문장만 넣었다. `NaN`은 값 이름이라 배우지 않은 문법이 아니다.
- 15: 다른 선택은 9-4 아래 `###`로 두는 것이다. 마지막 단계 코드와 완성 코드가 같은 파일(todo-4.js)이지만, 스타일 가이드의 미니프로젝트 구성("장 끝에 완성 코드와 해설")과 few-shot 예시 3을 따랐다.
- 9: 매개변수 이름 `filter`는 14장에서 그대로 복사해 쓸 함수라 바꾸지 않고 설명만 더했다.
- 확인 실행(node v24.13.0, scratchpad/review/09): todo-1~4.js 출력이 원고 실행 결과와 같음. 두 번 토글 조각은 `true`. 바꿔 보기 1은 `[ ] 4. 책 읽기` 추가와 `진행률: 33%`, `nextId` 5. 바꿔 보기 2는 세 목록 모두 `할 일이 없습니다.`와 `진행률: 0%`. `Math.round(1 / 3 * 100)`은 33, `2 / 3 * 100`은 66.666…이고 반올림 67. `getProgress`에서 삼항 연산자를 빼면 `[]`에서 `NaN`, 출력 `빈 목록 진행률: NaN%`. 매개변수 이름이 `filter`여도 `todos.filter()`가 동작함.
