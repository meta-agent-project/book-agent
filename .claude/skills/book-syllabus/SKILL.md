# book-syllabus

## 입력 확보
현재 대화의 브리프를 우선 사용하고, 없으면 `.book/interview/`에서 찾는다. 복수면 사용 브리프를 확인한다. 없으면 `book-interview` 진행 여부를 묻는다. 동의하면 인터뷰 후 이어 작성한다. 인터뷰 없이 진행하길 원하면 확인 가능한 정보로 설계하고 가정·미정 사항을 명시한다.

## 설계 원칙
- **학습목표에서 역산**해 장의 개수와 깊이를 정한다. 선수지식은 간략히, 후속과정에서 필요한 기반은 우선한다.
- 반드시 넣을 주제를 반영하고, 선택적으로 제외한 주제와 미정 항목에 대한 판단은 `가정한 것`에 기록한다.
- 01장에는 ‘실행 환경 준비’ 세부항목을 둔다. 과정에서 사용할 도구 설치·설정·첫 실행과 코드 유형별 실행 방법을 이 항목에 모은다. 이후 장에 환경 준비 항목을 반복하지 않는다.
- 목차는 **장 > 세부목차**로 구성한다. 각 세부항목은 `번호 + 제목 + 한 줄 설명(무엇/왜)`으로 적고 적합한 항목에는 `실습: 결과물`을 덧붙인다.
- 일반 장 끝에 결과물을 만드는 연습문제 **2~3개 제목**을 둔다. 에러 메시지·예외 처리 학습은 해당 주제의 실습과 연습문제에서 다룬다. 에러를 막는 기술은 그 세부항목에서 막기 전 에러를 보인다.
- 이론·실습 중심: 주제 덩어리가 끝나는 지점에 독립 `[미니프로젝트]` 장, 마지막에 앞 결과물을 조립하는 `[종합 프로젝트]` 장을 둔다. 프로젝트 장에는 사용한 장·핵심 기능을 표시하고 연습문제는 생략한다.
- 프로젝트형: 프로젝트 구현 단계를 장으로 만들고 세부항목에 `개념: ...`을 표기하며 각 장 시작에 `checkpoint-{NN}`을 기록한다. 프로젝트를 만드는 과정 자체가 전체 실습이다. 장 끝에는 일반 장과 같이 연습문제 **2~3개 제목**을 둔다.

## 출력 형식

```markdown
# 강의계획서: {주제}
- 날짜: {YYYY-MM-DD}
- 브리프: {파일 경로/대화 내용}

## 강의 개요
| 항목 | 내용 |
|---|---|
| 학습목표 | ... |
| 대상·선수지식 | ... |
| 후속과정 | ... |
| 강의방법 | ... |
| 실행 환경 | ... |

## 가정한 것
{미정 항목에 대한 가정, 제외한 주제/없음}

## 목차
1. {1장 제목}
2. {2장 제목}
...
N. [종합 프로젝트] {이름}

## 세부목차
### 1장. {제목}
- 1-1 {항목명}
  - {무엇을 왜 배우는지}. 실습: {만들 결과물}
- 1-2 {항목명}
  - {한 줄 설명}
- 연습문제
  - {문제 제목}
  - {문제 제목}

### N장. [미니프로젝트] {이름}
- 사용하는 장: {범위}
- 예제: {원고에서 만듦/외부 예제}
- N-1 {핵심 기능}
  - {설명}
```

프로젝트형은 각 장 제목 아래 `- 시작 코드: checkpoint-{NN}`을 넣고 세부항목 설명에 `개념: ...`을 사용한다. `[미니프로젝트]`와 `[종합 프로젝트]` 장은 이론·실습 중심일 때만 둔다.

## 마무리
초안을 보여 주고 장 순서·연습문제 형식·프로젝트 소재 등의 수정을 받는다.

목차가 확정되면 `[미니프로젝트]`·`[종합 프로젝트]` 장마다 예제를 원고에서 만들지, 다른 곳에서 만든 예제를 가져올지 묻는다. 원고에서 만드는 장은 `book-manuscript`가 코드까지 쓴다. 외부 예제 장은 강사가 수업 때 따로 둔 예제를 열어 라이브 코딩하므로 원고에는 실습 제목만 남는다. 답은 장 제목 아래 `- 예제: 원고에서 만듦` 또는 `- 예제: 외부 예제`로 적는다.

그다음 저장 승인을 받으면 `.book/syllabus/{YYYY-MM-DD}-{주제-slug}.md`에 저장한다. 다음 단계는 `book-manuscript`다.
