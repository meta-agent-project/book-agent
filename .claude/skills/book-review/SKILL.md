# book-review

## 역할
**원고 한 장의 표현과 형식**을 검수한다. 개념·실행 결과·계획서 적합성의 정확성 검증은 `book-manuscript`의 책임이다. 문체 교정과 내용·서식 개편을 구분한다. 기본 검수에서는 코드·출력·수치·고유명사·제목·문단·목록·표 구조를 보존하고 고칠 표현만 삭제·치환한다. 내용 오류와 구조 변경은 별도로 기록해 book-manuscript의 내용 개편 단계에서 처리한다.

## 1. 준비
먼저 [과정별 집필·개편 흐름](../book-manuscript/references/authoring-workflow.md)을 읽고 대상 과정의 원고폴더·설계폴더를 선택한다. 집필 후 자동 검수에도 같은 기준을 적용한다. 아래 경로는 선택한 과정으로 바꿔 사용한다.
`{설계폴더}/`과 `{원고폴더}/`은 프로젝트 루트 기준이고, `references/`와 `scripts/`는 이 스킬 폴더 기준이다.

대상 경로가 있으면 해당 파일을, 장 번호가 있으면 `{원고폴더}/{NN}장-*.md`를 선택한다. 미지정이면 `{설계폴더}/manuscript/ledger.md`에 기록된 장 중 `{설계폴더}/review/{NN}장-검수.md`가 아직 없는 가장 최근 장을 제안한다.

다음 기준을 읽는다.
- `.claude/skills/book-manuscript/references/style-guide.md`: 문체(1장), 오류 학습 범위(4장), 코드(5장), 읽기 쉬움(8장 R-1~R-9), MD 가독성(9장 MD-1~MD-5)
- `{설계폴더}/manuscript/course-setup.md`: 코드 컨벤션 예외
- 과정 설정의 코드 few-shot 경로가 있으면 해당 문서: 예제의 구성·복잡도 기준. 현재 교재에 채택한 범위만 적용한다
- `{설계폴더}/syllabus/`와 `ledger.md`: 학습자 수준·해당 장 범위·이미 배운 내용
- `../book-manuscript/references/title-style.md`: 공통 제목·문체·보존·완료 기준
- `references/spacing.md`, `references/korean-style.md`

## 2. 일곱 가지 검사
| 검사 | 실행·판단 방식 |
|---|---|
| 코드 | `node .claude/skills/book-review/scripts/check-code.mjs <원고 경로>` 실행. 과정별 들여쓰기(기본 2칸), 탭, 후행 공백, 따옴표, 쉼표·콜론·연산자 주변 공백, 세미콜론 등 점검. `?`가 붙은 추정 진단은 직접 판단 |
| 띄어쓰기 | `spacing.md`에 따라 보호 영역 밖 본문과 장 내 표기 일관성 확인. 문체 교정에서는 코드 문자열·주석의 띄어쓰기도 그대로 유지 |
| 문체 | `korean-style.md`에 따라 합니다체·개념어 유지, 간결한 교재 문장으로 교정. 교재 예외 적용 |
| 읽기 쉬움 | 학습자의 선수지식과 ledger를 기준으로 R-1~R-9 검사. 코드·설명 추가·구조 변경이 필요한 사항은 별도 내용 개편 후보로 기록한다 |
| MD 가독성 | `node .claude/skills/book-review/scripts/check-markdown.mjs <원고 경로>` 실행. 제목 계층, 목록 속 코드 블록, 본문·목록 줄 끝의 불필요한 역슬래시, 한 줄 한 문장, 한 문장 문단 연속, 블록 제목, 표 셀 검사. 일반 줄바꿈에 역슬래시를 요구하지 않는다. 문체 교정에서는 문단·제목·목록·표 구조를 보존하고 구조 진단은 따로 기록한다 |

코드 검사 스크립트의 블록 유형 분류를 확인한다: `기본 문법`은 문법, `예제 N-k`·`실습 코드`·파일명·`<!DOCTYPE`는 완결 코드, `실행 결과`·text 블록은 출력, 나머지는 코드 조각으로 판단한다. 코드 조각은 **0칸 들여쓰기에서 시작**하는 형태로 제안하며, 원본 예제와 변경 부분을 대조한다. 변수·함수는 뜻이 드러나는 camelCase를 권장한다. 과정별 예외를 우선 적용한다. `course-setup.md`가 규칙을 완화하면 해당 진단을 버리고, 금지 항목을 더하면(예: `var` 금지) 어긴 코드를 `CONVENTION` 규칙으로 보고한다.

**검사 범위:** 기존 제목은 보존하고 제목 후보와 판단을 별도 보고서에 기록한다. 제목 개편이 요청되면 계획서를 먼저 수정한다. 코드 블록·인라인 코드·실행 결과·오류 메시지·직접 인용은 공백까지 유지한다. 표의 문구를 다듬어도 행·셀 구조와 보호 영역은 유지한다.

| 추가 검사 | 실행·판단 방식 |
|---|---|
| 제목·문체 후보 | `node .claude/skills/book-review/scripts/check-style.mjs <원고.md> --json`. 회상·예고·긴 문장·상투구·번역투·반복·제목 후보를 수동 판단. 자동 치환하지 않음 |
| 보존 | `node .claude/skills/book-review/scripts/check-preservation.mjs <백업.md> <원고.md> --json`. 보호 영역·구조·수치 검사. `--terms <고유명사목록.json>`으로 지정 명칭 추가 검사. 의미·고유명사는 실제 diff로도 수동 대조 |

**긍정형 검토 기준:** 일반 개념·실습의 예제는 정상 동작하는 결과를 보여 주도록 점검한다. 에러·실패 결과는 에러 처리를 배우는 세부항목과 에러를 막는 기술을 설명하는 곳에 두고, 학습 의도와 처리 과정을 확인한다. 에러를 막는 기술인데 막기 전 에러를 보이지 않았으면 보고한다. 그 밖의 예제·바꿔 보기에 습관처럼 붙은 에러 시연도 보고한다. 에러 학습 세부항목에서 의도적으로 틀리게 쓴 코드와 연습문제의 고칠 거리는 형식 진단에서 제외한다. 수정안은 원래 의미와 코드 동작을 보존하는 **최소 변경**으로 작성한다.

## 3. 보고서 작성
사용자가 항목마다 판단하지 않게 한다. 문체 교정 범위의 발견마다 추천안 하나를 정해 반영하고, 반영한 목록을 보고서에 기록한다. 제목·내용·코드·구조 변경 후보는 별도로 기록한다. 사용자는 되돌릴 번호만 고른다.

### 3-1. 번호와 추천안
- 같은 유형의 반복 문제는 한 항목으로 묶고 관련 줄 번호를 모두 적는다.
- 모든 발견에 보고서 전체 연속 번호를 붙인다. 변경 목록과 상세 보고서는 같은 번호를 쓴다.
- 수정안이 둘 이상이면 하나를 추천안으로 정하고, 다른 선택은 상세 보고서에만 적는다.
- 기존 제목은 이번 본문 교정에서 바꾸지 않고 검토 결과와 이유만 기록한다. 제목 개편은 사용자가 지정한 별도 범위에서 계획서부터 반영한다.
- 스크립트 진단 중 직접 판단해 버린 것은 번호를 붙이지 않는다.

### 3-2. 변경 목록 (채팅과 상세 보고서 맨 앞)
반영을 마친 뒤 보여 준다. 한눈에 보이게 짧게 쓴다.
- 바꾼 내용은 `현재 → 수정안`에서 바뀌는 낱말만 쓴다. 긴 문장을 나눈 수정은 "긴 문장 분리"처럼 무엇을 했는지만 쓴다. 새 정의나 설명을 넣는 일은 별도 내용 개편 후보다.
- 이유는 규칙 ID 대신 쉬운 말 한 구절로 쓴다(예: "맞춤법", "정의 없이 씀", "짧은 절 뒤 쉼표").
- 반영하면서 추천안을 고친 항목은 이유 칸에 "반영 중 고침"을 붙이고 표 아래에 한 줄로 설명한다.
- 발견이 없는 분야와 버린 진단은 표 아래 한 줄로 모은다.
- 마지막 줄에 되돌리는 방법을 쓴다.

```markdown
**{N}장 검수: {n}건 반영** · 변경률 {x}% · 상세: `{설계폴더}/review/{NN}장-검수.md`

| 번호 | 위치 | 바꾼 내용 | 이유 |
|---|---|---|---|
| 1 | 424줄 | 아니오 → 아니요 | 맞춤법 |
| 2 | 14줄 | 에 있어서 → 에서 | 번역투 |
| 3 | 150줄 | 복합 대입 연산자 → 복합 할당 연산자 | 1장 "할당"과 통일 |

문제없음: 코드, 띄어쓰기, MD (스크립트 진단 16건은 기본 문법 식 형태라 제외)

**되돌리기:** 되돌릴 번호만 답한다(예: `3 되돌려`). 없으면 다음으로 넘어간다.
```

제목·내용·코드·구조 변경 후보가 있으면 표 아래에 따로 기록한다. 이번 본문 교정에서 반영하지 않은 이유도 적는다.

### 3-3. 상세 보고서
`{설계폴더}/review/{NN}장-검수.md`에 저장한다. 맨 앞에 3-2의 변경 목록을 넣고, 그 아래에 분야별 상세 표를 둔다. 코드 공백은 `·` 기호로 표시한다. 빈 검사는 `없음`이라고 쓴다.

```markdown
# {N}장 검수 보고서
- 원고: {경로}
- 검수일: {YYYY-MM-DD}
- 요약: 코드 {n} / 띄어쓰기 {n} / 문체 {n} / 읽기 쉬움 {n} / MD {n} / 기타 {n}

## 변경 목록
{3-2의 변경 목록}

## 코드
| 번호 | 원고 줄 | 블록 | 규칙 | 현재 | 수정안 |
|---|---|---|---|---|---|
## 띄어쓰기
| 번호 | 원고 줄 | 규칙 | 현재 | 수정안 |
|---|---|---|---|---|
## 문체
| 번호 | 원고 줄 | 패턴 | 현재 | 수정안 |
|---|---|---|---|---|
## 읽기 쉬움
| 번호 | 원고 줄 | 규칙 | 현재 | 수정안 |
|---|---|---|---|---|
## MD 가독성
| 번호 | 원고 줄 | 규칙 | 현재 | 수정안 |
|---|---|---|---|---|
## 기타
| 번호 | 원고 줄 | 내용 | 현재 | 수정안 |
```

## 4. 반영
1. 원본을 `{설계폴더}/review/backup/{NN}장.{YYYYMMDD-HHMM}.md`로 백업한다.
2. 문체 교정 범위의 추천안만 반영한다. 제목과 내용·코드·구조 변경 후보는 보고서에 별도로 남긴다. 새 설명·비유·사례를 넣지 않으며 좋은 문장은 그대로 둔다.
3. 반영 전에 추천안을 확인한다. 사용자가 미리 보지 않으므로 이 단계가 승인을 대신한다.
   - 코드 동작, 실행 결과, 사실 오류는 문체 교정에서 수정하거나 설명을 추가하지 않는다. 별도 내용 개편으로 처리하고 실제 실행·검증 후 문체 교정을 다시 수행한다.
   - 문체는 합니다체와 개념어, 원래 의미를 유지하며 다듬는다. 수정이 새 규칙 위반(연결어미 쉼표 등)을 만들지 않는지 본다.
   - 문체 교정에서는 문단 순서·소제목·목록·표 구조를 유지한다. 긴 문장만 같은 문단에서 나눈다. 연결 문장 추가·문단 재구성·목록 전환·제목 단계 변경은 별도 내용·서식 개편 범위다.
4. 코드·Markdown·제목·문체 검사와 백업 대비 보존 검사를 실행한다. 제목·문체 후보 처리와 의미·고유명사·조건 보존의 수동 검토를 보고서에 기록한다. 코드·Markdown 통과만으로 완료를 선언하지 않는다. 보존 검사가 실패하면 원문으로 복원한 뒤 다시 검사한다. 보호 영역이 동일하면 기존 도표·실행 결과를 유지한다. 파일·줄 참조를 점검한다.
   - 검토 HTML이 있거나 집필 흐름에서 검수 중이면 최종 원고·이미지·도표로 갱신한다. LF·CRLF를 모두 처리하며 Mermaid 개수·내용을 원고와 대조하고 실제 브라우저에서 표시를 확인한다. 비교 HTML의 변경 전 쪽은 백업을 유지한다.
5. 백업과 결과를 비교해 변경률을 계산한다. 변경률이 30%를 넘으면 과도한 교정 가능성을 알린다.
6. 상세 보고서 끝 `## 반영 결과`에 반영 번호·보류 후보·변경률과 계산 기준·백업 경로를 남긴다. 원고 Markdown에는 교정한 원고만 쓰고 채팅에는 결과와 보고서 경로를 간결하게 알린다.
7. 사용자가 되돌릴 번호를 답하면 백업을 보고 그 항목만 원래대로 돌리고, `## 반영 결과`에 되돌린 번호를 더한다.

변경률 계산(SequenceMatcher 기준):
```bash
python - "<백업 경로>" "<원고 경로>" <<'PY'
import sys, difflib
a = open(sys.argv[1], encoding='utf-8').read()
b = open(sys.argv[2], encoding='utf-8').read()
print(f'변경률 {100 * (1 - difflib.SequenceMatcher(None, a, b, autojunk=False).ratio()):.1f}%')
PY
```

## 5. 재사용 규칙
사용자가 적용 위치와 범위를 이미 정해 진행을 요청했으면 그 승인 범위에 반영한다. 과정별 코드 스타일을 검수할 때는 학습용 const·화살표 함수·이벤트 등록·위임 등을 단순화 대상으로 오인하지 않는다. 원고의 코드뿐 아니라 코드 인용, 준비 안내, 실행 결과 캡처도 변경된 예제와 맞는지 확인한다.

반복되는 피드백은 반영할 위치를 골라 사용자에게 한 번 묻는다. 공통 집필 기준은 `.claude/skills/book-manuscript/references/style-guide.md`, 과정 예외는 `{설계폴더}/manuscript/course-setup.md`, 띄어쓰기 관례는 `references/spacing.md`에 반영한다.

## 문체 교정 출력
