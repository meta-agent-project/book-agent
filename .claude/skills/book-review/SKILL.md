# book-review

## 역할
**원고 한 장의 표현과 형식**을 검수한다. 개념·실행 결과·계획서 적합성의 정확성 검증은 `book-manuscript`의 책임이다. 검수 중 발견한 내용 문제도 추천안 하나를 정해 반영하되, 4장의 확인 절차를 거친다.

## 1. 준비
`.book/`과 `book/`은 프로젝트 루트 기준이고, `references/`와 `scripts/`는 이 스킬 폴더 기준이다.

대상 경로가 있으면 해당 파일을, 장 번호가 있으면 `book/{NN}장-*.md`를 선택한다. 미지정이면 `.book/manuscript/ledger.md`에 기록된 장 중 `.book/review/{NN}장-검수.md`가 아직 없는 가장 최근 장을 제안한다.

다음 기준을 읽는다.
- `.claude/skills/book-manuscript/references/style-guide.md`: 문체(1장), 오류 학습 범위(4장), 코드(5장), 읽기 쉬움(8장 R-1~R-9), MD 가독성(9장 MD-1~MD-5)
- `.book/manuscript/course-setup.md`: 코드 컨벤션 예외
- `.book/syllabus/`와 `ledger.md`: 학습자 수준·해당 장 범위·이미 배운 내용
- `references/spacing.md`, `references/korean-style.md`

## 2. 다섯 가지 검사
| 검사 | 실행·판단 방식 |
|---|---|
| 코드 | `node .claude/skills/book-review/scripts/check-code.mjs <원고 경로>` 실행. 탭, 2칸 단위 들여쓰기, 후행 공백, 따옴표, 쉼표·콜론·연산자 주변 공백, 세미콜론 등 점검. `?`가 붙은 추정 진단은 직접 판단 |
| 띄어쓰기 | `spacing.md`에 따라 본문·코드 속 한국어 문자열·주석과 장 내 표기 일관성 확인 |
| 문체 | `korean-style.md`에 따라 합니다체·개념어 유지, 간결한 교재 문장으로 교정. 교재 예외 적용 |
| 읽기 쉬움 | 학습자의 선수지식과 ledger를 기준으로 R-1~R-9 검사. 코드 변경이 필요한 사항도 추천안을 정하고 4장 확인 절차를 따른다 |
| MD 가독성 | `node .claude/skills/book-review/scripts/check-markdown.mjs <원고 경로>` 실행. 제목 계층, 목록 속 코드 블록, 본문·목록 줄 끝의 불필요한 역슬래시, 한 줄 한 문장, 한 문장 문단 연속, 블록 제목, 표 셀 검사. 일반 줄바꿈에 역슬래시를 요구하지 않으며 문단을 묶거나 나눌 때 원문 문장 유지 |

코드 검사 스크립트의 블록 유형 분류를 확인한다: `기본 문법`은 문법, `예제 N-k`·`실습 코드`·파일명·`<!DOCTYPE`는 완결 코드, `실행 결과`·text 블록은 출력, 나머지는 코드 조각으로 판단한다. 코드 조각은 **0칸 들여쓰기에서 시작**하는 형태로 제안하며, 원본 예제와 변경 부분을 대조한다. 변수·함수는 뜻이 드러나는 camelCase를 권장한다. 과정별 예외를 우선 적용한다. `course-setup.md`가 규칙을 완화하면 해당 진단을 버리고, 금지 항목을 더하면(예: `var` 금지) 어긴 코드를 `CONVENTION` 규칙으로 보고한다.

**검사 범위:** 계획서에서 온 제목은 고치지 않고 `사용자 확인`으로 남긴다(계획서와 다른 장까지 바뀌기 때문). 인라인 코드·실행 결과·오류 메시지 원문은 원형을 유지한다. 코드 블록의 한국어 문자열·주석은 띄어쓰기만 판단한다. 표는 한글·가독성·MD 구조를 확인한다.

**긍정형 검토 기준:** 일반 개념·실습의 예제는 정상 동작하는 결과를 보여 주도록 점검한다. 에러·실패 결과는 에러 처리를 배우는 세부항목과 에러를 막는 기술을 설명하는 곳에 두고, 학습 의도와 처리 과정을 확인한다. 에러를 막는 기술인데 막기 전 에러를 보이지 않았으면 보고한다. 그 밖의 예제·바꿔 보기에 습관처럼 붙은 에러 시연도 보고한다. 에러 학습 세부항목에서 의도적으로 틀리게 쓴 코드와 연습문제의 고칠 거리는 형식 진단에서 제외한다. 수정안은 원래 의미와 코드 동작을 보존하는 **최소 변경**으로 작성한다.

## 3. 보고서 작성
사용자가 항목마다 판단하지 않게 한다. 발견마다 추천안 하나를 정해 그대로 반영하고, 반영한 목록을 보여 준다. 사용자는 되돌릴 번호만 고른다.

### 3-1. 번호와 추천안
- 같은 유형의 반복 문제는 한 항목으로 묶고 관련 줄 번호를 모두 적는다.
- 모든 발견에 보고서 전체 연속 번호를 붙인다. 변경 목록과 상세 보고서는 같은 번호를 쓴다.
- 수정안이 둘 이상이면 하나를 추천안으로 정하고, 다른 선택은 상세 보고서에만 적는다.
- 사용자에게 묻는 것은 계획서에서 온 제목 수정 하나뿐이다. 이것만 `사용자 확인`으로 따로 둔다.
- 스크립트 진단 중 직접 판단해 버린 것은 번호를 붙이지 않는다.

### 3-2. 변경 목록 (채팅과 상세 보고서 맨 앞)
반영을 마친 뒤 보여 준다. 한눈에 보이게 짧게 쓴다.
- 바꾼 내용은 `현재 → 수정안`에서 바뀌는 낱말만 쓴다. 문장을 새로 넣은 수정은 "터미널 정의 문장 추가"처럼 무엇을 했는지만 쓴다.
- 이유는 규칙 ID 대신 쉬운 말 한 구절로 쓴다(예: "맞춤법", "정의 없이 씀", "짧은 절 뒤 쉼표").
- 반영하면서 추천안을 고친 항목은 이유 칸에 "반영 중 고침"을 붙이고 표 아래에 한 줄로 설명한다.
- 발견이 없는 분야와 버린 진단은 표 아래 한 줄로 모은다.
- 마지막 줄에 되돌리는 방법을 쓴다.

```markdown
**{N}장 검수: {n}건 반영** · 변경률 {x}% · 상세: `.book/review/{NN}장-검수.md`

| 번호 | 위치 | 바꾼 내용 | 이유 |
|---|---|---|---|
| 1 | 424줄 | 아니오 → 아니요 | 맞춤법 |
| 2 | 14줄 뒤 | 터미널 정의 문장 추가 | 정의 없이 씀 |
| 3 | 150줄 | 복합 대입 연산자 → 복합 할당 연산자 | 1장 "할당"과 통일 |

문제없음: 코드, 띄어쓰기, MD (스크립트 진단 16건은 기본 문법 식 형태라 제외)

**되돌리기:** 되돌릴 번호만 답한다(예: `3 되돌려`). 없으면 다음으로 넘어간다.
```

`사용자 확인`이 있으면 표 아래에 따로 두고 추천과 다른 선택을 한 줄로 쓴다.

### 3-3. 상세 보고서
`.book/review/{NN}장-검수.md`에 저장한다. 맨 앞에 3-2의 변경 목록을 넣고, 그 아래에 분야별 상세 표를 둔다. 코드 공백은 `·` 기호로 표시한다. 빈 검사는 `없음`이라고 쓴다.

```markdown
# {N}장 검수 보고서
- 원고: {경로}
- 검수일: {YYYY-MM-DD}
- 요약: 코드 {n} / 띄어쓰기 {n} / 문체 {n} / 읽기 쉬움 {n} / MD {n} / 기타 {n}

## 변경 목록
{3-2의 변경 목록}

## 코드
| 번호 | 원고 줄 | 블록 | 규칙 | 현재 | 수정안 |
|---|---|---|---|---|---|
## 띄어쓰기
| 번호 | 원고 줄 | 규칙 | 현재 | 수정안 |
|---|---|---|---|---|
## 문체
| 번호 | 원고 줄 | 패턴 | 현재 | 수정안 |
|---|---|---|---|---|
## 읽기 쉬움
| 번호 | 원고 줄 | 규칙 | 현재 | 수정안 |
|---|---|---|---|---|
## MD 가독성
| 번호 | 원고 줄 | 규칙 | 현재 | 수정안 |
|---|---|---|---|---|
## 기타
| 번호 | 원고 줄 | 내용 | 현재 | 수정안 |
|---|---|---|---|---|
## 추천 근거
- {번호}: {수정안이 둘 이상이었던 항목의 다른 선택과 추천 이유}
```

## 4. 반영
1. 원본을 `.book/review/backup/{NN}장.{YYYYMMDD-HHMM}.md`로 백업한다.
2. 모든 추천안을 반영한다. `사용자 확인` 항목만 남겨 둔다.
3. 반영 전에 추천안을 확인한다. 사용자가 미리 보지 않으므로 이 단계가 승인을 대신한다.
   - 코드 동작, 실행 결과, 사실(값·동작·에러 메시지)에 관한 문장을 바꾸거나 새로 넣으면 그 코드를 실제로 실행해 문장이 맞는지 확인한다. 틀리면 추천안을 고쳐 반영하고 "반영 중 고침"으로 알린다.
   - 문체는 합니다체와 개념어, 원래 의미를 유지하며 다듬는다. 수정이 새 규칙 위반(연결어미 쉼표 등)을 만들지 않는지 본다.
   - 읽기 쉬움·MD 수정에는 필요시 연결 문장 추가, 문단 묶기와 나누기, 줄 풀이의 하이픈 목록 전환, 제목 단계·블록 배치를 적용한다.
4. 두 검사 스크립트를 다시 실행하고, 도식 글자를 고쳤으면 도식도 다시 잰다. 파일·줄 참조가 맞는지 점검한다.
5. 백업과 결과를 비교해 변경률을 계산한다. 변경률이 30%를 넘으면 과도한 교정 가능성을 알린다.
6. 채팅에 3-2의 변경 목록을 보여 준다. 상세 보고서 끝 `## 반영 결과`에 `반영 {번호} / 사용자 확인 {번호} / 변경률 x% / 백업 경로`를 남긴다.
7. 사용자가 되돌릴 번호를 답하면 백업을 보고 그 항목만 원래대로 돌리고, `## 반영 결과`에 되돌린 번호를 더한다.

변경률 계산(SequenceMatcher 기준):
```bash
python - "<백업 경로>" "<원고 경로>" <<'PY'
import sys, difflib
a = open(sys.argv[1], encoding='utf-8').read()
b = open(sys.argv[2], encoding='utf-8').read()
print(f'변경률 {100 * (1 - difflib.SequenceMatcher(None, a, b, autojunk=False).ratio()):.1f}%')
PY
```

## 5. 재사용 규칙
반복되는 피드백은 반영할 위치를 골라 사용자에게 한 번 묻는다. 공통 집필 기준은 `.claude/skills/book-manuscript/references/style-guide.md`, 과정 예외는 `.book/manuscript/course-setup.md`, 띄어쓰기 관례는 `references/spacing.md`에 반영한다.
