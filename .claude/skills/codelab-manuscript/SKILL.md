# codelab-manuscript

## 역할과 입력
**한 번에 한 장**을 작성하고 확인받는다. 각 장은 수강생이 앞 장에서 배운 지식만으로 따라갈 수 있게 만든다.

| 층 | 읽을 자료 | 목적 |
|---|---|---|
| 공통 기준 | `references/style-guide.md`, `references/few-shot.md` | 문체·블록·코드·검수 기준 및 형식 예시 |
| 과정 | `.codelab/interview/`, `.codelab/syllabus/`, `.codelab/manuscript/course-setup.md` | 목표·대상·세부목차·환경·도메인 |
| 진행 | `.codelab/manuscript/ledger.md` | 앞 장의 개념·API·명칭·미룬 내용 |

경로는 프로젝트 루트 기준이다. `references/`는 이 스킬 폴더 내부를 뜻한다. 집필 전에 `references/style-guide.md`와 `references/few-shot.md`의 실제 내용을 모두 읽고 시각자료 기준과 완성 예시도 확인한다. few-shot에서는 **형식만** 참고하며 실제 주제와 실행 환경은 과정 설정을 따른다.

## 절차
1. **계획서 확인:** `.codelab/syllabus/`에서 대상을 선택하고 계획서의 브리프를 읽는다. 계획서가 없으면 `codelab-syllabus` 작성 여부를 확인한다.
2. **과정 설정:** `course-setup.md`가 있으면 읽는다. 최초 작성 시 아래 항목을 브리프·계획서로 채워 사용자에게 확인받아 저장한다. 실행 환경이 불명확하면 실제 실행 도구를 질문한다.
3. **장 선택:** 지정한 장을 우선한다. 미지정이면 ledger의 다음 미작성 장을 제안한다. 이전 장 없이 진행하면 선수 지식과 코드 연속성에 대한 제한을 밝히고 진행 여부를 확인한다.
4. **장별 질문:** 계획서의 해당 장 세부항목·연습문제 제목을 채팅에 보여 주고, 비중 조정 제안이 있으면 이유와 함께 덧붙인다. 한 번에 질문한다: “수강생이 막히는 지점, 원하는 비유·예시, 비중 조정이 있나요? 없으면 ‘없음’.” 응답을 장부에 기록한다. ‘없음/알아서’면 계획서 비중을 따른다.
5. **연속성 확인:** ledger를 읽는다. 없으면 첫 장이므로 아래 필수 필드로 새로 만든다. ledger를 읽고 앞 장에 나온 용어·문법·API·파일명·함수명을 이어 쓴다. 새 개념은 해당 장에서 이해할 만큼 설명하고, 이전에 미뤄 둔 주제 중 이번 장 해당 사항을 다룬다.
6. **집필:** 계획서의 장 제목·세부목차 번호와 이름을 유지한다. 장 유형과 강의방법에 맞춰 `style-guide.md`의 구조·코드 형식을 적용한다. **정의 → 쉬운 설명·필요한 시각자료 → 기본 문법 → 완결 예제·실행 결과 → 따라하기 실습(전체 코드) → 연습문제 → 정답과 해설** 중 해당 소제목에 필요한 요소를 배치한다. 실제 소제목 구성은 계획서·스타일 가이드를 우선한다. 아래 ‘시각자료 구성’에 따라 설명할 흐름·분기·관계·구조·상태 변화·비교를 확인하고, 이해를 돕는 시각자료를 해당 설명 가까이에 실제로 작성한다.
7. **검증:** 기본 문법의 형태와 실제 실행 예제를 구분한다. 완결 예제·따라하기·바꿔 보기·정답을 세션 임시 폴더(scratchpad)에 원고의 파일명 그대로 저장해 실행하고 서술한 결과와 비교한다. 코드 조각은 바탕 예제에 적용한 뒤 확인한다. `.js`는 Node.js, `.html`은 가능하면 브라우저로 검증한다. 브라우저 실행이 어려우면 직접 검토하고 미실행 항목을 명시한다. 에러 학습 항목은 에러 이름·메시지·위치·처리 결과까지 확인한다.
8. **초안 검토:** style-guide.md의 시각자료 기준, 읽기 쉬움(R-1~R-9), MD 가독성(MD-1~MD-5), 검수 체크리스트를 확인한다. 복잡한 흐름·분기·관계를 글로만 설명해 필요한 시각자료가 빠졌는지도 확인하고 보완한다. Mermaid의 문법과 화살표·조건·용어가 본문 및 예제 코드와 일치하는지 검증한다. 렌더링 도구가 있으면 실제로 렌더링하고, 없으면 직접 검토한 범위를 밝힌다. `node .claude/skills/codelab-review/scripts/check-markdown.mjs <원고 경로>`로 형식 검사도 수행한다. 초안과 실행 검증 결과를 보여 주고 피드백을 반영한다.
9. **확정·저장:** `book/{NN}장-{장 제목}.md`에 저장하고 ledger를 갱신한다. NN은 두 자리, 파일명 공백은 `-`, 대괄호는 제거한다. `book/`은 장 원고 전용이다. 저장 후 `codelab-review` 검수 또는 다음 장 진행을 선택받는다.

## 시각자료 구성
- 세부항목마다 시각화할 설명이 있는지 검토한다. 실행 순서, 조건 분기, 요소 간 관계, 데이터 구조, 상태 변화, 값 비교를 글로 따라가기 어려운 곳에는 시각자료를 포함한다.
- 흐름·순서·분기·관계·ER은 Mermaid, 메모리 칸·배열 칸·화면 배치는 텍스트 도식, 값·특성 비교는 표로 표현한다. 상세 선택 기준과 형식은 `style-guide.md` 6장을 따른다.
- `**시각자료 — 그림 이름**` 아래 실제 Mermaid 코드 또는 텍스트 도식을 작성하고, 그림 아래에 읽어야 할 핵심을 짧게 설명한다. 도식은 이미지 생성 프롬프트로 대체하지 않는다.
- 장마다 그림 개수를 강제하지 않는다. 단순한 문법 설명은 생략할 수 있지만, 시각자료가 필요한 설명을 생략 대상으로 처리하지 않는다.
- few-shot의 변수 선택 흐름도와 할 일 추가 흐름도를 형식 예시로 삼는다. 현재 장에서 아직 배우지 않은 조건이나 기능을 그림에 미리 넣지 않는다.

## course-setup.md 필수 필드
```markdown
# 원고 과정 설정: {주제}
- 강의계획서: {경로}
## 실행 환경
- 에디터: ...
- 실행 방법: {코드 유형별 도구와 명령}
- 버전: ...
- 예제 형태 규칙: {예: 콘솔=단일 .js, DOM=단일 .html}
## 실습 파일 규칙
- {장별 폴더·파일 이름}
## 예제 도메인
- {일반 예제와 프로젝트 소재}
## 코드 컨벤션 예외
- {없음/과정별 예외}
```

## ledger.md 필수 필드
```markdown
# 원고 진행 장부: {주제}
## 장별 기록
### {N}장. {제목}
- 상태: 초안 / 확정
- 파일: {book/ 경로}
- 설명한 개념: ...
- 쓴 문법과 API: ...
- 프로젝트 파일과 이름: {파일·함수·데이터 구조/해당 시}
- 장 끝 코드 상태: {checkpoint/프로젝트형만}
- 강사 메모: ...
## 앞으로 미룬 설명
- {주제 → 다룰 장}
```

## 원고를 만드는 긍정형 기준
- **정상 작동하고 올바른 결과를 보여 주는 코드**를 개념 예제·따라하기·바꿔 보기의 기본값으로 사용한다.
- **오류와 실패 사례는** 계획서에서 `에러 메시지 읽기`, `예외 처리`, `요청 실패 처리` 등을 배우는 세부항목에서 교육목적과 예상 결과를 명시하여 다룬다.
- **따라하기**에는 처음부터 끝까지 실행 가능한 전체 코드를 제공한다. **연습문제**는 수강생이 직접 해결하도록 문제와 정답·해설을 분리한다.
- **기본 문법**은 문법 형태를 보여 주며, **예제**에는 코드와 검증된 실행 결과를 제시한다. **코드 조각**은 적용할 원본 예제와 변경 위치를 명확히 한다.
- 같은 기능군은 **한 실습에서 비교**하고, 코드의 변수·함수·파일명은 장 전체에 걸쳐 일관되게 사용한다.
- 학습자가 찾아보기 쉽도록 제목은 **개념 이름 중심**으로 쓰고 장의 세부목차는 계획서를 그대로 유지한다.
- 설명은 **짧은 문단과 명확한 정의**, 학습 수준에 맞는 구체적 예시로 쓴다. 코드 위치는 줄 번호보다 실제 구문을 인용해 안내한다.
- 공통 문체·코드 컨벤션·R/MD 규칙은 `style-guide.md`를 단일 기준으로 사용한다.

동일한 피드백이 반복되면 과정 한정 기준은 `course-setup.md`, 여러 강의에 공통인 기준은 `style-guide.md`에 반영할지 확인한다.
