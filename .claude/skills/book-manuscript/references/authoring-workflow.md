# 과정별 집필·개편 흐름

새 원고와 기존 원고 개편 모두에 적용한다. 사용자가 정한 작업 범위·예외를 우선하고, 이미 합의된 기준은 파일에서 이어받는다.

## 과정과 기준 선택

| 과정 | 원고폴더 | 설계폴더 |
|---|---|---|
| JavaScript | `book/` | `.book/` |
| React | `book2/` | `.book2/` |

다른 과정은 지정된 원고폴더와 연결된 설정을 사용한다. 대상이 모호하고 여러 과정이 해당할 때만 확인한다. 스킬 본문의 `{원고폴더}`·`{설계폴더}`는 선택한 과정의 경로다. 설정에 명시한 원고·이미지·브리프·계획서·장부·개편 상태 경로가 기본 경로보다 우선한다.

읽는 순서:

1. 대상 과정의 `manuscript/course-setup.md`와 연결된 변경 합의.
2. 그 설정이 가리키는 코드 few-shot.
3. 연결된 최신 계획서와 브리프.
4. `manuscript/ledger.md`와 개편 상태표(있는 경우).
5. 공통 `style-guide.md`·`title-style.md`와 원고 형식 `few-shot.md`.

우선순위는 현재 사용자 지시 → 저장된 과정별 합의·설정·코드 few-shot → 최신 계획서 → 공통 가이드다. 충돌을 발견하면 이미 합의된 변경을 관련 파일에 동기화한다. 새 판단이 필요한 충돌만 사용자에게 확인한다. 코드 few-shot은 예제 구성·복잡도 기준이고 공통 few-shot은 문체·장 구성의 예시다. JavaScript의 let·onclick·인라인 CSS를 React에 옮기는 등 다른 과정의 규칙을 자동 적용하지 않는다.

새 few-shot을 받으면 원본 경로·분석한 범위·채택한 특징·적용 범위를 과정의 코드 few-shot 문서에 저장하고 course-setup에서 연결한다. 원본을 전부 분석하지 않았다면 그 범위를 분명히 적는다. 목차 변경은 계획서에 먼저 반영하고 본문·교차 참조·장부를 맞춘다. 코드 단순화는 학습목표·실행 환경·필수 동작을 유지한다.

## 집필부터 검수까지

- 지정한 장·범위를 끝까지 수행한다. 한 장 요청은 한 장, 전체 요청은 전체다. 기존에 합의한 장별 비중·프로젝트 형식·스타일을 다시 질문하지 않는다. 합의가 없는 최초 설계의 질문은 book-interview·book-syllabus 절차를 따른다.
- 기존 원고를 고치면 변경 전 원고·영향받는 이미지·설정을 대상 과정의 review 또는 revision 폴더에 백업한다. 이미 보존된 기준본을 덮어쓰지 않는다. 새 원고에는 변경 전 내용을 만들어 넣지 않는다.
- 과정별 프로젝트 형식을 먼저 확인한다. React의 라이브코딩 안내·Spec 장에 일반 장의 전체 코드·정답 형식을 강제로 추가하지 않는다.
- 예제·따라하기·바꿔 보기·정답과 코드 인용을 함께 맞춘다. 새 원고는 서술한 결과를 실제 실행과 대조하고, 개편은 유지할 동작과 변경한 동작을 구분해 확인한다. 변경된 목차나 사용자 의도로 달라진 동작을 과거 결과와 억지로 같게 만들지 않는다.
- JSX·TSX는 과정 설정의 실제 프로젝트·버전에서 빌드하고 필요한 상호작용을 브라우저로 확인한다. 스크립트 문법 검사만으로 React 예제 실행을 검증했다고 기록하지 않는다. 실행 결과 캡처는 실제 예제와 조작 순서에 맞춰 갱신한다.
- 집필·코드·내용 검증을 끝낸 원고를 백업한 뒤 book-review의 문체 교정 → 보존 검사 → 최종 검수를 자동으로 수행한다. 사용자가 검수를 따로 요청할 때까지 기다리지 않는다. title-style.md를 공통 기준으로 사용하며 기존 제목·문단 순서와 코드·출력·수치를 보존한다. 내용 오류는 별도로 기록하고 집필·내용 개편으로 돌아가 수정·실행 검증 후 다시 백업한다. 문체 교정 중 코드·설명 추가나 문단 재구성을 하지 않는다. 보호 영역이 동일하면 기존 실행 결과·캡처·도표를 유지한다.
- 장부에는 작성·개편 여부와 실행 검증 여부를 나누어 기록한다. 사용자가 확정하기 전에는 검수를 마쳤어도 초안이다. 범위를 일괄 승인받았으면 다음 장 진행을 매번 다시 묻지 않는다.

## 브라우저 검토

- 요청 범위의 집필·검수를 마치면 기본적으로 검토 HTML을 만들어 브라우저에 직접 연다. 사용자가 MD만 요청하거나 브라우저 열기를 생략하도록 지시하면 그 지시를 따른다.
- 새 원고: 읽기용 화면. 여러 장이면 장 선택과 소제목 이동을 제공한다.
- 기존 원고 개편: 백업한 변경 전과 최종 수정 후를 좌우 반반으로 표시한다. 각 영역의 개별 스크롤, 선택적인 연동 스크롤, 장·소제목 이동을 제공한다. 변경 전 이미지도 백업에서 읽는다.
- 출력은 `docs/{원고폴더 이름}-preview/`처럼 과정별로 나누고 course-setup의 지정 경로가 있으면 그것을 따른다. 다른 과정의 비교 HTML을 덮어쓰지 않는다. 이 프로젝트의 JavaScript 비교 구현 `docs/book-style-comparison/`은 참고할 수 있지만 book2 경로와 상태표를 자동으로 대신하지 않는다.
- 원고·표·코드·결과 이미지·Mermaid를 모두 표시한다. Mermaid는 book-mermaid의 웹 렌더러와 디자인을 사용하고 원고의 코드 블록은 유지한다. PNG/SVG 파일 내보내기는 명시적으로 요청한 경우에만 한다. 웹 화면의 인라인 도식은 허용한다.
- Markdown 처리와 도표 추출은 LF·CRLF를 모두 인식한다. 원고의 Mermaid 블록 수·내용을 렌더링된 도표와 대조한다. 비교 화면은 양쪽을 각각 확인한다. HTML 생성 시 누락·오래된 도표를 오류로 처리한다.
- HTML 생성 후 `node .claude/skills/book-manuscript/scripts/update-preview-images.mjs {검토.html}`을 실행한다. 이 명령은 `assets/preview-images.css`와 `assets/preview-images.js`를 중복 없이 포함한다. 화면 표시 크기는 최대 560×280px이며 이미지 확대 보기와 키보드 조작을 제공한다.
- `node .claude/skills/book-review/scripts/check-visuals.mjs {원고폴더}`로 미완성 자리·파일 누락·이유 없는 텍스트 시각자료를 검사한다.
- 실제 브라우저에서 모든 대상 장의 도표 수·표시 크기·라벨·이미지 로드·코드 표시·스크롤을 확인한다. SVG 태그가 존재하는 것만으로 렌더링 성공을 판정하지 않는다. 불가피하게 확인하지 못한 항목은 보고하고 검증 완료로 기록하지 않는다.

## 완료 보고

원고 경로, 적용 범위, 실제 검증 결과, 검토 HTML 경로, 백업 경로(개편 시)를 간결하게 알린다. 막힌 항목은 별도로 명시한다. 다음 집필에 필요한 새 합의는 과정 설정·few-shot·계획서·장부에 저장하며 채팅에만 남기지 않는다.
