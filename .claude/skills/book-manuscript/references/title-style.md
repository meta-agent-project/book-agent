# 교재 제목과 본문 문체

book-syllabus·book-manuscript·book-review가 함께 사용하는 기준이다. 현재 사용자 지시가 우선한다. 기존 원고의 문체 교정에서는 제목을 보존하고, 제목 검토 결과는 별도 보고서에 남긴다.

## 제목 작성과 개편

- 제목은 학습하는 핵심 개념·원리·기능·문제·해결 방법을 드러낸다. 간결한 명사형을 우선한다.
- 정확하고 통용되는 기술 용어를 쓴다. 불필요하게 어려운 말과 강사의 구어체를 피한다.
- 상위 개념을 하위 제목에서 불필요하게 반복하지 않는다. 서로 다른 내용을 구분하는 데 필요한 기술 용어는 유지한다.
- 제목만 읽어도 학습 내용과 구조가 드러나야 한다. 명사형을 강제하지 않으며 내용을 특정하는 질문형을 허용한다.
- “~해 봅시다”, “~하기”, “~합니다”, “알아보기”, “살펴보기”, “이해하기”와 모호한 질문·정보 없이 긴 제목은 검토한다. 어미만 보고 자동으로 바꾸지 않는다. “회원 등급 변경 실습”처럼 결과가 명확한 실습 제목은 허용한다.
- 제목 개편은 계획서를 먼저 고치고 원고·문제·정답·참조·장부를 함께 맞춘다. 본문 문체 교정에 제목 변경을 섞지 않는다.

| 유형 | 예 |
|---|---|
| 개념 | State란?, Props란?, 불변성이란? |
| 원리 | React의 렌더링 원리, 이벤트 처리 구조 |
| 기능 | State 업데이트, 조건부 렌더링 |
| 문제 | 객체의 직접 변경, Props Drilling |
| 해결 | 불변성을 유지하는 객체 업데이트 |
| 비교 | State와 Props의 차이, CSR과 SSR 비교 |
| 실습 | 회원 등급 변경 실습, 게시글 목록 구현 |

## 본문 다듬기

사람 강사가 쓴 교재처럼 다듬는다. 주로 빼고 바꾸며, 고칠 필요가 없는 문장은 그대로 둔다. 한국어 사람 문체의 패턴은 book-review/references/korean-style.md를 항목별로 검토한다.

| 기준 | 적용 |
|---|---|
| 말투 | 합니다체. 보호 영역을 뺀 한글 음절이 40개를 넘는 문장은 같은 문단에서 나눈다. “여러분”은 문단당 한 번까지 |
| 현재 개념 | 이전·다음 장 회상과 예고를 빼고 현재 개념을 직접 설명한다. 코드 사용에 필요한 파일·경로·선수조건은 그대로 둔다 |
| 메타·상투구 | “~에 대해 알아보겠습니다”, “~라고 할 수 있습니다” 같은 군더더기를 뺀다. 실제 가능성·조건·추정은 단정으로 바꾸지 않는다 |
| 번역투 | “~에 있어서”는 문맥에 따라 “~에서”로, “~을 진행하다”는 그 동작의 동사로 바꾼다 |
| 리듬 | 같은 종결 표현은 연속 네 문장까지. 공통 어미 “~니다” 자체를 반복 위반으로 세지 않는다. “~할 수 있습니다”는 세부항목별 네 번까지이며 학습목표는 제외한다 |
| 구조·서식 | 문단 순서·소제목·목록·표 구조를 유지한다. 이모지를 쓰지 않고 새 강조·글머리표를 추가하지 않는다 |
| 내용 | 새 비유·설명·사례를 넣지 않는다. 내용 오류나 빠진 정의는 별도로 기록하고 내용 개편 단계에서 처리한다 |

문체 교정 결과로 반환하는 Markdown에는 다듬은 원고만 담는다. 검수 기록·변경 목록은 원고 밖의 보고서에 저장한다.

## 보존과 완료 조건

1. 코드 블록·인라인 코드·실행 출력·오류 메시지·직접 인용은 문자열·주석·공백까지 그대로 보존한다. 보호 영역은 한글 띄어쓰기 교정에서도 제외한다.
2. `⟦CODE n⟧`는 문자·개수·순서와 소제목·문단 안의 배치를 보존한다. 문장 분리에 따른 줄 번호 변화는 허용하며 다른 문단으로 이동하지 않는다.
3. 수치·고유명사·식별자·파일 경로·링크와 기능·조건·횟수·결과의 의미를 보존한다. 순수한 장 안내와 중복 설명에서 장·예제·연습문제 참조 번호를 제거한 것은 보고서에 기록한다. 코드 적용에 필요한 파일·예제 위치는 유지하며 나머지 수치는 한 글자도 바꾸지 않는다.
4. 코드·내용 검증을 끝낸 원고를 백업한 후 다듬는다. 제목·문체 후보는 check-style.mjs로 탐지하고 사람이 문맥을 판단한다. 자동 치환을 하지 않는다.
5. check-preservation.mjs로 백업과 결과의 보호 영역·구조·수치를 대조한다. 본문에 인라인 코드가 없는 고유명사도 사람이 변경 diff와 대조한다. 알려진 고유명사 목록은 --terms로 추가 검사한다. 자동 검사만으로 의미·고유명사 보존을 증명했다고 쓰지 않는다.
6. 코드·Markdown 검사, 문체·제목 수동 검토, 보호 검사와 별도 검수 기록을 모두 완료해야 통과한다. 제목 후보를 보존한 이유와 수정하지 않은 문체 후보도 기록한다.

순서는 집필·내용 개편 → 코드·내용 검증 → 문체 다듬기 → 보존 검사 → 최종 검수다. 보호 검사 실패 시 교정을 완료로 표시하지 않고 보호 대상을 원문으로 복원한다. 코드나 설명을 고쳐야 하면 내용 개편으로 돌아가 실행 검증을 마친 뒤 다시 백업하고 다듬는다.
