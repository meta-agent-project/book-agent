# 원고 설명 요소 조합

- 날짜: 2026-10-10
- 참여: 사용자, Claude

## 배경

5장 5-3 일급 객체 원고가 틀렸다.
정의에 특징을 섞었고, 성질 개념에 "왜 필요할까"를 붙였다.
고친 뒤 style-guide.md에 사용자가 하지 않은 말("정의를 좁히지 않는다", 일급 객체 예시)이 규칙으로 들어갔다.
원인을 따라가 보니 스타일 가이드가 순서 하나를 고정해 두고 빼는 방식이라 원고가 틀에 맞춰졌다.

## 핵심 논의

- 일급 객체의 세 조건(변수 할당, 인수, 반환값)은 정의가 아니고 특징이다
- 정의는 쉬운 한 문장이고, 그 뒤에 특징을 나열하고 코드 예제로 보인다
- 이 순서는 원래 스타일 가이드에 있었다. 규칙이 모자란 게 아니라 지키지 않았다
- 설명 순서는 개념마다 다르다. 고정 순서 대신 요소를 골라 조합한다
- 사용자가 준 요소 표와 유형별 조합 예시를 쓴다

## 결론

- 정의와 쉬운 설명은 한 블록으로 늘 맨 앞에 둔다
- 고정 순서를 없애고 요소 표(선택 기준)와 유형별 조합 예시로 바꾼다. 조합 예시는 출발점이다
- 문제 해결형도 정의 → 문제 상황 → 해결 방법 → 코드 예제로 쓴다
- 주의점을 요소에 더한다. 문장으로 쓰고 에러 실행은 기존 "에러를 다루는 범위"를 따른다
- "좋은 점" 규칙과 "정의를 좁히지 않는다" 규칙은 뺀다
